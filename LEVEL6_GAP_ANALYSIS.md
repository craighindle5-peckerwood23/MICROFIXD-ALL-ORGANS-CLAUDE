# Microfixd Level-6 Extension Gap Analysis

## Baseline and Target

The existing build provides **150 registered organs**, Tier-0 Paragon decisions, bounded sandbox evolution, Supabase-backed durable records, OmniRouter/Plugin Registry boundaries, a browser-safe local screenshot procedure, and a governed operations console. The new directive extends this to a complete **eight-layer operating model** with **at least 172 organs**, explicit multi-agent and multi-tenant procedures, compute and web-use boundaries, a GitHub change-control pipeline, automatic repair proposals, and a central holographic mission-control surface.

> This assessment is an implementation checklist. Requirements marked **planned** will be implemented as executable governed procedures, registered organs, durable records, and tested routes; they are not considered fulfilled by this document alone.

| Layer | Current status | Implementation gap to close |
|---|---|---|
| 0 — Constitutional | Constitution, doctrine, identity, autonomy and Paragon policies exist. | Make boot sequencing and safe-mode state explicit and auditable. |
| 1 — Organ architecture | Registry, kernel, telemetry, sandbox, and generic fallback exist. | Add explicit boot, wiring, repair, and health-triggered repair procedures. |
| 2 — Cognitive | Deterministic planning, reflection, memory recall, and metacognition exist. | Add a durable six-role multi-agent registry, routing, collaboration, oversight, and arbitration flow. |
| 3 — Memory | Working/long-term/executive memory is implemented. | Partition durable memory and agent records by tenant context. |
| 4 — Execution | Goals, plans, queues, retries, sandbox, guards, and local Puppeteer controls exist. | Add tenant workflow controls, action routing, and safely governed web-use requests. |
| 5 — Self-evolution | Candidate generation, static sandbox validation, rollback/fallback, and approval gates exist. | Add health-triggered repair proposals and a GitHub change request lifecycle: sandbox → tests → Paragon → PR request → CI/deploy/rollback boundaries. |
| 6 — Safety | Security, drift, reality, output qualification, audit, and Paragon escalation exist. | Add tenant isolation enforcement, explicit safe-mode control, and all-agent preflight records. |
| 7 — Infrastructure | Docker, Railway, Codespaces, Azure/GCP configuration, health, metrics, runtime and phenotype exist. | Add compute capability discovery, GPU/eGPU/cluster routing profiles, and multi-runtime/device posture records. |

## Required Organ Expansion

The registry will expand from **150 to 189 organs**. The additional thirty-nine organs cover five missing control planes:

| Expansion family | Added organs | Execution form |
|---|---:|---|
| Organ lifecycle and repair | 4 | Native/composed repair, boot, wiring, and telemetry procedures. |
| Multi-agent cognition | 11 | Native agent registry/router plus composed role procedures and arbitration. |
| Compute and multi-runtime | 7 | Native local capability discovery plus governed remote compute adapters. |
| Web and GitHub evolution | 4 | OmniRouter/Plugin Registry adapters with Paragon review and audit. |
| Multi-tenant enterprise and mission control | 13 | Tenant-scoped durable entities and controlled UI/action procedures. |

## Safety Boundaries Preserved

| Requirement | Enforced implementation boundary |
|---|---|
| Self-fixing / self-modifying | The system may inspect, create a sandbox candidate, run bounded validation, and create a governed change request. It may not silently alter active source, secrets, plugins, deployments, or production infrastructure. |
| GitHub evolution | The deployed runtime creates a Paragon-governed change request and can route an approved request through the GitHub Plugin Registry adapter. Creating a real pull request, merging, CI deployment, and rollback remain protected actions. |
| Web use | Every external web interaction must be an OmniRouter request through an enabled Plugin Registry manifest. The current local-only screenshot feature is retained for the service's own console and is not an arbitrary-browser bypass. |
| GPU / cluster | Runtime capability discovery is local and read-only. Remote GPU, eGPU, distributed, and cluster jobs are provider adapters that require a configured route, cost policy, and Paragon decision. |
| Multi-tenancy | Tenant identification, constitution, doctrine, plugin allowlists, workflows, memory, agents, and audit records are scoped and enforced server-side. Global Tier-0 Paragon remains above tenant policy. |
| Holographic UI | The interface visualizes system state with a browser-native holographic head. It does not represent consciousness, biometric identity, or an unverified physical avatar. |

## Mandatory End-State Tests

The final verification will require a clean boot with durable storage, 189-organ registry integrity, all eight layers reported, multi-agent execution with audit records, cross-tenant rejection, safe-mode halt, repair proposal creation, GitHub/web/compute adapter denial without approved configuration, UI tenant switching and approval controls, and a local-console screenshot that exposes no secrets.
